## ユーザー確定事項（変更禁止）
- 指示書 v1.0 の「絶対条件」15項目すべて
- 3AI連携はAPIを使わず、依頼文コピー＆回答貼付方式（課金ゼロ・個人情報の自動送信なし）
- 自動同期（iPhone⇄PC）は最終的に導入するが：任意機能／同期停止でもIndexedDBだけで使える／オフライン可／無料枠優先・超過見込みは事前警告／JSONバックアップは残す／学校実データは同期しない／採用前に「選定理由・無料枠・移行可能性」をユーザーに確認
- 各Phase終了時に「実装済み・未実装・テスト結果・エラー/既知の問題・次に行うこと」を報告し、引継ぎに反映
- テスト全合格まで、そのPhaseを完了扱いにしない
- 既存コードを理由なく全面書き換えしない（Phase 1の仕組みは維持）
- 実機確認が終わるまで「実機確認待ち」を引継ぎから消さない
- 要望を採用しても仕様書は自動で書き換えない（「仕様へ反映」→変更案→差分確認→確定の流れのみ）
- 確定Versionは上書き・削除しない（変更は新しいVersionで。古いVersionは残す）
- 「話すだけ」の相談メモはプロジェクトを削除しても残し、「プロジェクトは削除されています」と表示する
- Markdownのファイル名は英数字（中身は日本語）。日本語ファイル名はv1完成後の改善候補
- 3AI比較で採用した案・URLのアイデアは要望箱（未検討）までしか入れない。仕様書を直接変えない
- Factoryは採用案もAIも勝手に決めない（おすすめAIは表示のみ）
- AIへ渡す文章はコピー前に個人情報チェック（自動判定＋最後はユーザーが目視確認：正式採用）。URLは取得制限を回避しない（正式採用）
- テストの不合格・エラー・修正の記録は合格後も消さない
- 「完成」は確定仕様・必須テスト全合格・重大問題0件・引継ぎ・バックアップ可能・実機確認完了をすべて満たすときだけ。「使用可能」とは区別
- テスト不合格・重大問題からの「次にやること」は、ユーザーが確認して追加（自動で大量に作らない）
- 7プロジェクト：Vintage Hunt／STORM／連合チーム予定管理／野球教材動画＋練習メニュー／学校 出欠・行事・三者面談管理／野球部会計／家族スケジュール・タスク管理／健康・減量管理。開発順もこの順。**野球成績・オーダーアプリは対象外（追加・統合しない）**
- **既存アプリはゼロから作り直さない**：現在の状態を取り込む → 基準Versionとして保存 → 確定仕様と照合 → 必要な改良だけ要望箱へ → 次Versionで改良
- **既存アプリのURL・ソースコードが渡されていなければ推測して登録しない**。仕様と違っていても勝手に既存アプリのコードを変更しない
- 7件の既存アプリは、Factory完成後にユーザーが探して伝える（それまで「既存アプリ：未確認」）
- 学校Surfaceの既存データ（Factory＋7件）を絶対に変更・削除しない。空の端末のデータでクラウドを上書きしない。同期は Sync-1〜5 の段階ごとに実機確認
- メールアドレスをコード・GitHub・Rulesに書かない。無料枠のリセット時刻・再開時期は断定しない
- 学校の生徒等の個人情報を3AIへ自動送信しない。Factoryの開発データと実際の学校運用データを分離する
- PWAからApple Healthを取得できないなら、できるように見せかけない。有料APIを勝手に採用しない
