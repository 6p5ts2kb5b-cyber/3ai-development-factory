# 3AI Development Factory v1.1.0 リリース記録（2026-10-10）

## 追加：確定仕様との照合「JSONから判定候補を読み込み」
既存アプリタブの「確定仕様 vX との照合」で、判定候補のJSON（例：STORM_36items_import.json）を読み込み、確認してから一括反映する。

### 流れ
1. 「JSONから判定候補を読み込み」→ ファイルを選ぶ（読むだけ。まだ保存しない）
2. 確認画面：行ごとに「JSONの項目名・判定」と「Factoryの仕様項目（所属セクション・本文）・名前の一致」を表示。対応済み／要手動対応／対応できない／既存判定あり／上書き対象の件数、JSONの判定の内訳と反映後の件数（予定）を表示
3. 要手動対応の行は、内容を確認して「対応で正しい」にチェックするまで反映できない。対応できない行があるときは反映できない（件数を無理に合わせない）
4. 既存の判定がある行は「保持」が既定。行ごとに「上書きする」を選んだときだけ上書き（メモは残す）
5. 「先にバックアップを保存（おすすめ）」→「N項目の反映を確定」→ 最後の確認 → 1回の保存で反映。「取り消す」ではなにも保存しない
6. 反映後に保存内容を読み直し、JSONの判定と反映後のFactoryの件数を表示。各項目のメモに根拠と「実機動作確認済みではありません」を記録

### 安全対策
- JSONは JSON.parse で読むだけ（実行しない）。決まった項目（番号・項目名・判定・確認方法・根拠）だけを取り出す
- 200KB・200行まで。秘密鍵・APIキーらしき文字があれば読み込まない。個人情報らしき根拠は保存しない。表示はすべて文字として扱う
- プロジェクト名・確定仕様の版・項目数・番号の重複/欠落が合わなければ読み込まない
- 番号だけで対応させない：番号の位置の仕様項目と項目名の重なり（50%以上）を確認。ほかの項目の方が15ポイント以上似ていれば要手動対応
- 確認画面を開いたあとにプロジェクトや確定仕様が変わっていたら保存しない。保存に失敗したら何も変わらない
- ネットワークに接続しない（STORM本番アプリ・Supabaseにアクセスしない）

### STORM_36items_import.json の場合
- 34行が自動で対応。9番「3校の学校予定」と17番「複数グラウンド候補と状態」は、保存データの同名の項目（29番・26番）の方が名前が近いため要手動対応
- JSONの判定：実装済み17・一部7・未判定12。未判定のプロジェクトに反映すると、Factoryの照合も実装済み17・一部実装済み7・未判定12
